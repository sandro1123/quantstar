# QuantStar

QuantStar 是一个面向 A 股市场的量化选股与多智能体（Multi-Agent）投研工程化框架。

本项目致力于解决量化选股策略从“本地原型验证”走向“全天候自动化生产运行”过程中的工程化问题。系统覆盖了多源行情清洗与容错、时点数据（Point-In-Time）防前视偏差、因子截面计算与动态调权、LLM 多空委员会辩论决策、推荐标的全生命周期状态机追踪，以及全天候调度运维体系。

## 一、核心定位与开源边界

### 1. 本项目提供什么
- 一套分层解耦、单向依赖的量化选股底层架构；
- 标准化的多源数据采集、时点数据（PIT）清洗与质量监控管道；
- 因子流水线引擎，包含 MAD 去极值、行业市值中性化与标准化；
- 基于多智能体的大模型多空辩论与结构化风控质检流程；
- 标的全生命周期状态机（从初筛、待买入、持仓到止损退出的完整跟踪）；
- 基于交易日历的生产定时调度、并发锁与健康探针。

### 2. 本项目不提供什么（重要）
- **本仓库不含任何开箱即用的高收益私有 Alpha 策略**；
- **本仓库不含历史行情数据库或财务数据文件**（仓库克隆后数据库为空，需自行接入数据源拉取）；
- **本仓库不含具体的实盘荐股记录、真实账户持仓与私有交易账本**；
- 代码内仅保留了 `mom20`（20 日动量）与 `vol20`（20 日波动率）两个示例因子，用于演示因子编写规范与引擎跑通。使用者需要自行开发专属因子并配置打分权重。

## 二、全天候生产工作流 (24-Hour Production Flow)

在标准交易日内，QuantStar 的各个模块按照交易所时刻协同运转：

```
 [08:00 晨间内参] 
       │ 读取前夜候选池与智能体多空辩论评级
       ▼
 [08:00 晨报推送] ──────────────────────────────────────────▶ 飞书/工作台 (推送早报)
       │
 [09:15-09:25 盘前竞价解析]
       │ auction_parse: 捕捉集合竞价撮合价、未撮合量、竞价高低开幅度
       ▼
 [09:25 盘前速报] ──────────────────────────────────────────▶ 校验入场条件，预警追高标的
       │
 [09:30-15:00 盘中动态扫描 (每 5 分钟循环)]
       ├─ 待买入标的 (Pending Entry) 触价检验 ──────────────▶ 满足 entry_low~entry_high 触发开仓
       ├─ 持仓标的 (Active) 五层阶梯出场监控 ──────────────▶ 触发硬止损/移动止损/ATR/死叉平仓
       └─ 日内风控检查 ────────────────────────────────────▶ 当日累计止损 >= 3 次触发熔断停买
       │
 [15:05 收盘结算]
       │ end_of_day: 冻结持仓市值、结算交易费用、核算账户现金流
       ▼
 [15:30 多源全量数据归集]
       │ daily_data_pipeline: 多源拉取日K线、资金流向、大宗交易、停牌清洗
       ▼
 [16:00 因子截面重算与动态调权]
       ├─ factor_update: 全市场截面因子计算、MAD去极值、行业市值中性化、Z-Score标准化
       └─ ic_feedback: 滚动计算因子 Rank IC 与 IC-IR，动态调整有效因子权重
       ▼
 [16:45 晚间复盘与次日候选推演]
       ├─ 截面初筛 Top N 候选标的
       └─ 调度 Agent 委员会（多头分析师 vs 空头风控官 vs 裁决官）进行多空对抗
       ▼
 [16:45 晚报生成与推送] ──────────────────────────────────▶ 产出全天损益归因与次日备选清单
       │
 [20:30 端到端健康审计]
       │ e2e_verification: 自动化回检数据新鲜度、持仓状态机连续性与配置一致性
       ▼
 [23:00 数据库与状态备份]
       │ db_backup: SQLite 备份引擎打包、校验指纹并同步至归档区
       ▼
 [周末休市期 步进优化]
       └─ wfo_gate: Walk-Forward Optimization (WFO) 步进验证样本外效率
```

### 支柱一：数据基座与防未来时点截面

#### 1. 5 源熔断与降级自愈
多源集成 AkShare、Tushare、Baostock、Easyquotation 等数据源。为各数据源建立独立熔断桶，单一数据源遭遇网络波动或限流时自动切换备选链路，记录降级标记并保障管道正常运行。

#### 2. 时点数据 (PIT) 真实公告日对齐
财报与基本面数据严禁按季度截止日（如 03-31、06-30）对齐，必须严格绑定上市公司真实公告披露日（`announced_at`）。避免回测在 4 月初使用尚未披露的财报数据造成虚假盈利。

#### 3. 停牌日 0 价污染源头清洗 (F-23 判例)
行情源在停牌日可能返回 `close = 0.0`。若直接入库会导致单日涨跌幅被误算为 `-100%`，击穿组合净值。QuantStar 在源头跳过退化记录，管道层将停牌日价格重置为 `pre_close`，涨跌幅记为 `None`，杜绝价格污染。

#### 4. 成交量/额对调纠偏与空报文三态分流 (判例 #186)
- **量额对调校验**：以均价中位数与现价区间比对，实时纠偏第三方接口偶发的 volume 与 amount 字段反向对调；
- **三态律**：严格区分 `NONE`（接口未执行，系统故障）、`EMPTY`（查到了但事实无数据，正常）与 `ERROR`（查询崩溃，异常），防止以零值或假绿掩盖故障。

### 支柱二：因子流水线与动态自适应调权

#### 5. 动态截面 MAD 去极值与方差标准化
为了确保不同股票的因子得分具备横向可比性，策略层通过绝对中位数去极值（MAD）将离群点裁剪至合理区间，再通过 Z-Score 进行方差标准化，消除极端值对排名的扭曲。

#### 6. 行业与对数市值 OLS 正交中性化
利用截面普通最小二乘回归（OLS），从因子得分中剥离申万一级行业哑变量以及对数总市值敞口，提炼纯 Alpha 收益，防止策略演变成单纯的小市值暴露或行业重仓。

#### 7. 滚动 Rank IC / IC-IR 自适应动态调权 (`ic_feedback`)
每日盘后统计各因子得分与未来 $N$ 日收益率的斯皮尔曼等级相关系数（Spearman Rank IC）及信息比率（IC-IR）：
- 稳定有效的因子自动提升在组合中的权重占比；
- 连续失效翻负的因子自动压低权重甚至降为零；
- 引入指数平滑阻尼机制，防止单日行情噪音引发权重剧烈摆动。

#### 8. 多模型多空委员会辩论质检与 Token 预算隔离
初筛出的候选标的进入智能体质检网络：多头分析师挖掘上涨催化剂，空头风控官排查质押/解禁/超买风险，中立裁决官综合输出置信度评分与逻辑论据。底层网关通过 `reasoning_floor`（6000~8000 tokens）为 CoT 推理模型提供独立预算下限，防止思考耗尽 tokens 导致回答为空。

#### 9. 集合竞价盘前微观形态即时解析 (`auction_parse`)
每个交易日 09:15~09:25 启动独立竞价管道，捕捉集合竞价撮合价、未撮合量与高低开幅度，在 09:25 盘前速报中直接给出开盘即时修正，预警开盘大幅不及预期或追高标的。

#### 10. 市场情绪周期与大盘环境识别 (Regime & Emotion Cycle)
内置大盘情绪状态机，跟踪连板高度、昨日涨停炸板率、跌停家数比等指标，自动划分市场阶段（主升、震荡、退潮、冰点）。在退潮期主动收紧入池门槛与开仓额度，实现顺周期进攻、逆周期防守。

### 支柱三：交易执行状态机与非对称赔率守卫

#### 11. 标的全生命周期状态机管理
标的在库中严格单向流动：`watch`（观察）➔ `pending_entry`（待买入）➔ `active`（持仓）➔ `exit_pending`（待卖出）➔ `exited`（已退出）。状态变更收敛于特定结算时点，杜绝盘中状态漂移。

#### 12. 入池三闸风控体系 (时效 / 价格 / 赔率)
买入单入池前必须经过严格三道硬门禁：
1. **时效闸**：超过 2 个交易日未撮合成交的计划强制失效作废；
2. **价格现实闸**：现价已破止损位（开仓即止损）或涨出入场区间上限的标的当场拦截；
3. **动态赔率守卫**：要求理论盈亏比 $\text{RR Ratio} = \frac{\text{Take Profit} - \text{Entry Mid}}{\text{Entry Mid} - \text{Stop Loss}} \ge 1.45$，过滤不对称平庸交易。

#### 13. 五层阶梯出场引擎
持仓标的每日依次接受五层退出逻辑检验：固定硬止损（-8%）、移动跟踪止盈（利润回撤保护）、ATR 波动自适应止损、均线技术死叉离场，以及最大持仓天数时间衰减退出。

#### 14. 全组合回撤迟滞带保护 (Hysteresis Drawdown Gate)
当整体投资组合净值回撤达到安全阈值（如 -8%）时，系统自动挂上熔断闩锁停止新开仓位，直到净值回升修复至恢复线（如 -5%）才允许解除，避免在临界点反复开平仓产生摩擦成本。

#### 15. 投后退出质量追踪与复盘归因 (`post_exit_tracker`)
标的卖出后自动设立 T+3、T+5、T+10 的检查点：若卖出后股价继续下跌，判定为避险成功（`correct_exit`）；若卖出后股价大幅上涨，判定为过早卖飞（`wrong_exit`）。长期统计胜率用于反向校准止损止盈带宽。

#### 16. 人机协同审批闭环 (Human-In-The-Loop, HITL)
支持全自动与半自动双模。入池建议可经飞书卡片或控制台推送到审批队列，支持人工一键批准或驳回，未及时审核单据自动超时撤销，兼顾风控灵活性。

#### 17. 纸盘模拟到实盘的毕业门禁 (Graduation Gate)
新策略或参数在部署前需在影子账本（Paper Trading）中持续运行 18~30 个交易日。只有当纸盘实际夏普比率达到样本外回测的 70% 以上且回撤未超标时，才允许晋级至生产实盘。

### 支柱四：生产运维、对账自愈与工程底座

#### 18. POSIX 文件锁并发写入控制 (`flock_guard`)
主存储使用 SQLite。所有写入型定时任务必须通过 `flock_guard.sh` 排队执行，配合超时看门狗，彻底避免多进程并发争抢写锁引发的 `database is locked` 崩溃。

#### 19. 真实落库对账自检工具 (`recon`)
内置 `python -m src.cli.main recon` 对账工具，穿透到底层数据表比对行数、时间戳与指纹，杜绝“任务显示 success 但实际零行入库”的静默故障。

#### 20. 11 类问题源自动聚合与派单台账 (`issues` CLI)
内置 `python -m src.cli.main issues daily` 指令，自动扫描任务日志、告警表、质量标记等 11 类问题源，按影响度识别级别与慢性病，支持一键生成每日系统体检报告。

## 四、十层解耦架构

系统在代码和逻辑上严格划分为十个层级，单向依赖：

```
                           ┌──────────────────────────────────────────────┐
```

| 层级 | 职责说明 |
|---|---|
| **Data Layer** | 行情源对接、数据清洗规范化、停牌与复牌处理、时点数据（PIT）公告日对齐 |
| **Strategy Layer** | 因子计算管线、MAD 极值处理、行业市值中性化、初筛候选池生成 |

| **Config Layer** | defaults → settings → profiles → local 四级覆盖，支持 JSON Schema 校验 |
| **Memory Layer** | 记录历史异常特征与经验，供复杂诊断参考 |

## 五、使用者前置准备与投入生产指南

如果你希望把 QuantStar 部署到自己的服务器上投入日常使用，请按以下步骤依次准备：

### 1. 运行环境配置
- **推荐解释器**：Python 3.11（强烈建议，生产测试基准基于 3.11 锁定；Python 3.12 在部分数学库中存在低位精度差异）；
- **操作系统**：Linux（推荐 Ubuntu 22.04 / 24.04）或 macOS。Windows 建议在 WSL2 环境下运行。

```bash
# 1. 克隆代码
git clone https://github.com/sandro1123/quantstar.git
cd quantstar

# 2. 创建并激活虚拟环境
python3.11 -m venv .venv
source .venv/bin/activate

# 3. 安装依赖（包含测试与开发工具）
pip install -e ".[dev]"
```

### 2. 数据源与环境变量配置
复制环境变量模板：
```bash
cp .env.example .env
```
根据实际情况修改 `.env` 中的配置项：
- **开发调试模式**（`CONFIG_ENV=dev`）：启动时不进行强制环境变量检查，默认可使用公开免鉴权数据源；
- **生产运行模式**（`CONFIG_ENV=prod`）：启动时执行强制项检查，必须提供主数据源 API Key 及飞书等通知渠道凭证；
- 消息通道凭据（如 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`）。

### 3. 历史数据初始化与日常采集
**新克隆的项目不会自带数据库文件**。首次运行时系统会在 `data/qs.db` 创建包含 80 余张表的 SQLite 基础结构。

因子计算（例如计算 20 日动量、20 日波动率）**依赖连续的历史 K 线数据**。若数据库为空，计算因子时将全部返回 `None`。
推荐的数据初始化路径：
1. **拉取历史日 K 线**：
   通过数据层管线拉取目标股票池最近 60~250 个交易日的历史 K 线：
   ```bash
   python -m src pipeline run kline
   # 或者执行历史回填脚本
   python scripts/backfill_valuation.py
   ```
2. **日常盘后增量采集**：
   在每个交易日收盘后（建议 15:30 之后），执行日常采集管道拉取当日最新行情：
   ```bash
   python -m src pipeline run daily_data_pipeline
   ```

### 4. 自定义因子开发与权重配置
仓库目前仅提供 2 个示例因子。投入生产前，你需要实现自己的因子逻辑：
#### (1) 编写因子代码
在 `src/strategy_layer/factors/` 目录下创建新文件（例如 `my_factor.py`）：
```python
from strategy_layer.factors.base import BaseFactor, FactorContext, FactorResult

class MyFactor(BaseFactor):
    name = "my_factor"
    category = "momentum"
    window_size = 20

    def compute(self, ctx: FactorContext) -> FactorResult:
        klines = ctx.klines
        if len(klines) < self.window_size:
            # 数据不足时必须返回 None，引擎会自动安全过滤
            return FactorResult(code=ctx.code, date=ctx.date, factor_name=self.name, score=None)
        
        score = (klines[-1]["close"] - klines[-self.window_size]["close"]) / klines[-self.window_size]["close"]
        return FactorResult(code=ctx.code, date=ctx.date, factor_name=self.name, score=float(score))
```

#### (2) 注册因子与调整权重
在 `src/strategy_layer/factors/__init__.py` 中引入并加入 `ALL_FACTORS` 列表：
```python
from strategy_layer.factors.my_factor import MyFactor

ALL_FACTORS = [
    ExampleMomentumFactor20,
    ExampleVolatilityFactor20,
    MyFactor,
]
```
在 `config/defaults/strategy.yaml` 中配置打分权重：
```yaml
strategy:
  factors:
    enabled:
      - my_factor
      - example_vol20
    weights:
      my_factor: 0.8
      example_vol20: 0.2
```

### 5. 大模型 (LLM) 接口配置
如需启用多智能体辩论（Agent Layer），需在 `config/defaults/llm.yaml` 中配置你可用的模型接口。
支持标准 OpenAI 兼容协议（包括本地部署的 Ollama / vLLM 或外部 API 网关）：
```yaml
llm:
  providers:
    - name: my-llm-primary
      url: http://localhost:11434/v1/chat/completions  # 本地 Ollama 示例
      model: deepseek-r1
      timeout: 60
      priority: 1
      # 如果使用具备思考链（CoT）推理模型，务必设置此项保证调用预算
      reasoning_floor: 6000
```

### 6. 报告定制与推送通道设置
- **仓库不含预设的静态报告文件**：所有盘前速报、晨报、午报、晚报均在定时调度触发时动态生成；
- **格式支持**：内置支持飞书富文本互动卡片（`feishu_card`）与通用纯文本（`text`）；
- **多通道扩展**：结合第三方库 `apprise`，支持平滑对接企业微信、钉钉、邮件及通用 Webhook；
- **自定义报告段落**：可通过继承 `Section` 与 `ReportBuilder` 编写专属报告段。详细教程请参阅：[docs/REPORT_CUSTOMIZATION.md](docs/REPORT_CUSTOMIZATION.md)。

### 7. 生产定时调度 (Crontab)
系统配备了基于交易日历自动触发的参考配置 `deploy/quantstar-crontab`。
核心调度时刻参考（工作日 1-5 运行）：
- `08:00`：早报生成与候选推送；
- `09:25`：盘前集合竞价分析；
- `09:30-15:00`：每 5 分钟盘中触价与出场监控（`intraday_scan`）；
- `15:30`：收盘全量数据管道采集（`daily_data_pipeline`）；
- `16:00`：因子截面全量重算与评分（`factor_update`）；
- `16:45`：晚报生成与复盘（`evening_report`）；
- `23:00`：数据库自动备份（`db_backup`）。

## 六、已知局限与生产注意事项

投入生产前，请务必了解以下客观技术边界：

1. **SQLite 并发锁限制**：
   系统主存储使用 SQLite。多进程同时写入容易出现 `database is locked` 错误。因此，**所有写入型定时任务必须通过 `scripts/flock_guard.sh` 包装执行**，保证同一时刻只有一个任务持有写连接；
2. **外部数据源稳定性与限流**：
   公开免费行情接口在交易高峰期可能遭遇限流或延迟。生产环境建议配置稳定的主备数据源，并在 `ops.yaml` 中配置合理的重试与超时时间；
3. **推理模型思考阶段的 Token 消耗**：
   使用 DeepSeek-R1 等推理模型时，模型会先在内部输出大量思维链内容。如果调用方设置的 `max_tokens` 过小（如默认 2000），会导致模型思考未完即被截断，返回内容为空。框架内通过 `reasoning_floor` 保证了下限，自行添加新 provider 时请务必留意此配置；
4. **节假日与停牌股**：
   系统内置交易所日历。非交易日大部分管道会自动跳过。遇到新股上市首日或长期停牌股复牌，由于无前收盘价或无历史成交量，部分因子会返回空值，属于正常防前视现象。
