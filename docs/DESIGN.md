# QuantStar 设计与实现

> **一句话定位**：QuantStar 是一套 A 股量化选股系统——每天从全市场约 5,500 只股票中选出少数候选，对每只推荐股做全生命周期跟踪，并在合适的时机给出入场/出场操作建议。它不是回测玩具，而是一台每天真实运转、自我观测、持续改进的生产机器。

**版本锚**：v0.19.0-dev ｜ 基线 main@29a2a99（2026-09-10 午后窗）｜ 十层 557 文件 / 约 5.4 万行 Python ｜ 466 测试文件 / 4,545 个测试 ｜ 生产库 84 表（K 线 1,283 万行 / 因子日表 712 万行）

本文写给两类读者：**接手开发的工程师**（看契约、看判例、看为什么这样设计）与**想理解系统在做什么的使用者**（看每天的产出怎么读）。文中"已实现"均有代码锚，"在途"如实标注——文档与代码同纪律：不虚报。

## 一、设计哲学

这些原则不是装饰性口号，每一条都对应至少一次真实事故。它们是系统的宪法。

**1. 诚实降级，禁止静默。** 数据不可达时显式标 `degraded`、报告段如实写"数据缺失"，绝不用零值、假数据或上一日的旧数冒充。血案：回测层曾因"卖出腿静默 continue"把零成交算成 -68%~-99% 的假亏损，每晚污染 8 行——修法是"没考试没分数"守卫（零成交时全部指标归零并标 `data_quality.valid=False`）。

**2. 少给数据，不给未来数据（PIT 双时态）。** 因子计算只能看到"当时能看到的数据"：财报用 `announced_at`（公告时点）而非报告期末对齐，新回填数据保守延迟 45 天生效。血案：财务数据曾按季末时点对齐导致 38 个报告期全部错位一天。

**3. 建了必须通电。** 写了代码、建了表、配了管道，但没接上调度、没被任何消费面读到=不存在。血案：D4 对账管道建好后 crontab 零行、runs 零行——"建了没通电"三重证（排程无条目+运行零记录+输出表不存在）成为验收任何新组件的标准检查。

**4. 观测面先于功能面。** 每个关键动作必须留下可对拍的痕迹（pipeline_runs 行、delivery_log 行、checkpoint 行），"可观测不可静默"。判断系统健康的第一硬证据源是 syslog 与 runs 表，不是任何人的口头汇报。

**5. 五态律。** 🟡（部分完成）不是完成态。任何"差不多好了"的件都按未完成对待。

**6. 少而精。** 推荐位 N=clamp(3,8) 浮动——宁可空缺不凑数。新闻分级"宁缺毋假"（无命中落噪声桶）。

**7. 单点必有对冲。** 任何数据类型只有唯一来源时必须登记依赖度账面并寻找备源。血案：主力数据源 fuyao 独占 13 类数据，一次断供就是涨停梯/竞价/财务三表全断。

**8. 状态变更收敛到单一时点。** 池状态迁移（推荐→跟踪→持仓→退出）只在收盘轮发生，盘中轮静默跳过——防状态漂移。

**9. 测试即契约。** 新功能 TDD 先行（RED 精确命中再 GREEN），存量断言落后于现实时要修断言而非绕过——但改口径必须全量复跑存量测试。

**10. 判例文化。** 每个坑都要沉淀为可复用的判例（病根→修法→为什么），写入交接册。系统不只是代码，是代码+判例库的总和。

## 二、十层架构与一天的生命周期

十个层各占 `src/` 下一个目录，禁自造分组。一天的真实运转（交易日，crontab 56 条腿）：

```
08:00  晨报组装+推送           ← report_layer / delivery_layer
09:00  盘前数据快照
09:25  盘前速报（09:15 竞价后）  ← report_layer（新编排）
09:30  开盘 → 盘中扫描每5分钟    ← execution_layer（域收窄至推荐+跟踪+持仓 ~15 只）
       ├─ 入场检查 / 出场检查 / 异动警示（agent_checkpoints 全程留痕）
12:00  午间报告
13:00  午后扫描继续
15:00  收盘轮 = 池维护日        ← execution_layer（三态建议留痕 action_records）
16:00  日线管道（fuyao/tushare 主源拉取）→ 因子计算（89 因子）→ ML 模型预测 →
       IC 反馈 → 因子权重更新    ← data_layer / strategy_layer
17:05  三源对拍（D4：kline 漏采/lhb/moneyflow 分桶判定） ← data_layer 观测件
17:35  结算：模拟盘日结 + benchmark 打分（PTS.benchmark_return 首值锚）
18:05  fx_settlement 补跑腿（benchmark 结算线所在）
19:05  chart_analysis 图表分析
20:00  晚报旗舰推送             ← report_layer 六段结构 → delivery_layer 白名单路由
22:05  变更窗（唯一生产变更时点）← ops_layer
23:00  数据库备份 + 日志轮转
```

**十层职责与契约**（每层一段，含关键判例）：

### 1. 数据层 data_layer（65 文件，最大层）
- **职责**：K 线/财务/估值/资金流/新闻/涨停梯等全市场数据采集、复权、对拍、新鲜度审计。
- **契约**：11 个源适配器（fuyao/tushare/akshare×2/gtimg/mootdx/同花顺/zzshare/easy_tdx/baostock/adata）走统一 `protocol.py` 接口；注册表 `registry.py` 管 `is_available` 门控+分型优先级+主备源；拉取侧落 `source` 标签（备源对拍的判源依据）。
- **关键判例**：拉取类作业一律夜间窗；写库前单表 dump 先行；表名想当然会踩"管道叫 stock_list 实际落 stock_info"（PRAGMA-first）；风险源 fail-closed 返回 None 而非空集。
- **在途**：207 只主源漏采补全（D3 族）、PIT 45 天回填（D1）。

### 2. 策略层 strategy_layer（109 文件）
- **职责**：89 个因子（动量/质量/技术/流动性/盘口四族…）+ ML 腿（xgb/lgb blend=0.2ml+0.8factor）+ IC 反馈衰减 + 因子生命周期治理。
- **契约**：`FactorContext` 统一喂料（含 shortterm_data 市场级盘口数据）；`engine.py` 5-Stage 管道；`lifecycle/` 退役线（连续 20 日横截面死因子触发冻结）+ ic_decay 刹车（20/60 日分层 0.4/0.6+IR>0.5 显著性闸+中位数<-0.03 降档观察）。
- **关键判例**：因子缓存三级（LRU 内存→factor_daily 库→实时计算）；70 个死因子是"当日横截面"非"20 日连续态"，退役线 09-20 后自然触发（宁慢十天不乱口径）。
- **在途**：ST-REGIME 情绪周期（人气榜/热门概念原料已备）、ST-PLAYBOOK 剧本。

### 3. Agent 层 agent_layer（63 文件）
- **职责**：七专家团（趋势/动量/价值/风险/技术/资金/news_intel 叙事者）+ 辩论链（多轮互看修订）+ 裁决官 + LLM 配额治理。
- **契约**：所有 LLM 调用走 `build_request` 工厂（12 外部消费点收口）；`AgentRequest` 九字段标准请求；专家有 LLM 腿与规则腿双轨——LLM 不可用时降级到规则腿并显式标注；配额真源=9router usageDaily sqlite 只读直读（预算-真消耗，不可达即 degraded 不静默沿用假数）。
- **关键判例**：盘中快速路径纯规则零 LLM（0.3% 阈值快速通过+临线 2% 才上 LLM+last_check_price 落库防未来）；mock 必须与管道新调用形态同步（kwargs 加了 mock 也要加）。
- **在途**：AG-DEBATE-V2（2 轮制+invalidation_conditions 条件失效声明）。

### 4. 回测层 backtest_layer（37 文件）
- **职责**：Hold/事件驱动等模式的净值追踪、成本模型、指标计算。
- **契约**：持有窗尾部按**交易日序列**推进（非自然日+5）；卖出腿缺价必须记名 `sell_data_missing`+warning（禁裸 continue）；未卖出持仓按最后已知价估值（禁 nav({}) 按 0 计）；零成交守卫全指标归零+`data_quality.valid=False`（持久化/消费面据此拒收）。
- **关键判例**：回测假数据病理链全修（四修点，见哲学 1）；部分窗口标 `partial` 与编排层语义对齐。
- **在途**：BT-FIX 修点① run() 接线收尾。

### 5. 执行层 execution_layer（34 文件）
- **职责**：股票池全生命周期（推荐池→跟踪池→持仓→退出三池一门）+ 三态建议引擎+盘中扫描+模拟盘交易+benchmark 打分。
- **契约**：`recommendation_advisor` 三态判定序=risk 否决→过期→价区→默认 wait；buy_now 必附条件单四件套（为什么选/在哪买/什么情况买/何时卖），wait_watch 附条件+有效期，pass 附原因；池退出三规则（X=8% 萎缩/N=10 日无信号，config 可调，落 exit_reason）；扫描域收窄口径=推荐+跟踪+持仓 15 只（全池 90 的 16.7%）。
- **关键判例**：veto 否决源列名必须对齐 agent_predictions 真表（created_at 非 decision_date——列名错会静默假绿）；盘中扫描域账实跑回放对拍（90→15 excluded=75）。
- **在途**：EX-4 CLI 挂线（窗官亲执）。

### 6. 报告层 report_layer（55 文件）
- **职责**：报告宪法 14 条的落地——晚报旗舰六段+盘前速报+晨报/午报+issue 日报+前瞻预演。
- **契约**：晚报六段固定序=**昨日推荐点评（信誉位置置顶）**→大盘总结→板块新闻→明日推荐四行结构（为什么选/在哪买/什么情况买/何时卖）→持仓管家→预演+系统健康；每段落 delivery_log 留痕；推荐位 N=clamp(3,8) pool-first 断层浮动。
- **关键判例**：编排改动必须与段清单逐一对拍（勿凭记忆——曾漏排 market_one_liner 被存量断言逮住）；信誉位置顶是"用户昨天看到的推荐今天必须被点评"的信任契约。

### 7. 投递层 delivery_layer（18 文件）
- **职责**：五通道（飞书群/DM/HITL DM/多维表格/主机归档）路由+白名单闸+送达回执。
- **契约**：push_rules 按"消息类型→通道语义"路由；FAN_OUT 收口（盘中警示单通道，根除双发）；每条投递落 delivery_log（判读送达率的唯一真相源）。
- **在途**：三端语义分工（群=技术报告/运维 app=P0+日结/用户 app=仪表盘）+旧 push_rules.yaml 后门删除。

### 8. 配置层 config_layer（4 文件，最小层）
- **职责**：defaults（出厂）+ local（本机覆盖）+ profiles（场景组合）三层分离；门禁七必填键（防生产装载残缺配置）；漂移哨兵。
- **契约**：新键必须登记 owner 层+变更纪律（配置宪法）；deepdiff 哨兵盯漂移。
- **在途**：键级文档化+5 个 .bak 沉积清账。

### 9. 运维层 ops_layer（21 文件）
- **职责**：管道编排（orchestrator）+心跳（pipeline_runs 即心跳）+告警去重状态机+自愈+混沌演练+问题台账（issues ledger）。
- **契约**：22:05 唯一变更窗+15:35 午后窗（双窗制）；crontab 变更窗内亲执双确认；flock 防并发；watchdog 看护每腿。
- **关键判例**：db_backup 假绿三夜（保留块恒偏 4.52pt——锚定绝对余量 GB 而非相对百分比）；满盘事故后纪律=单表写禁整库备份。

### 10. 记忆层 memory_layer（3 文件，最年轻层）
- **职责**：跨日教训与约束的存取，喂六专家与 IC 反馈。
- **契约**（三铁律）：写=evidence 必指来源+scope/kind 白名单+同域冲突 supersede；读=scope 过滤+recency×相关度 top-k+token 预算封顶；域=global/agent:/stock:/factor: 四前缀。
- **关键判例**：写入闸门防记忆污染（无证据的"感觉"不可入库）；每条记忆是 lesson/feedback/constraint 三型之一。

## 三、横切面：跨层宪法件

**PIT 双时态**：所有财务对齐用 announced_at；新数据 45 天保守回填期。
**白名单闸**：推送先过类型白名单再路由（宪法第 12 条）。
**排程真相源**：syslog+crontab+pipeline_runs 三面对拍，单口供不算数。
**完成判据文化**：每张卡带可验证验收锚（如"benchmark 首值=PTS.benchmark_return 非 NULL+快照行=活仓数"），判据达成才算收口。

## 四、完成形态：什么叫"问题全清+运行良好"

用判据定义，不用形容词：

1. 问题台账 D 系列（数据深水区）清零：PIT 回填完成、207 只漏采补全、三源对拍每日常态绿。
2. 晚报/速报连续 14 日准时零漏发，昨日推荐点评每交易日闭环。
3. benchmark 连续有值——每只推荐股都被打分（"考了多少分"），损益结论反哺策略层。
4. 因子退役线自然触发至少一轮（死因子被冻结而非继续占位）。
5. 4,545 测试全绿且新增回归零存量债。
6. 单源依赖度账面全部有对冲路径（fuyao 13 类逐一补备源）。

到达此形态时的系统：推荐少数股票→全程管家式跟踪→盘中警示→收盘复盘→次日改进建议→每晚 20:00 一份可信赖的旗舰晚报，而每一环都留痕、可对拍、可审计。
